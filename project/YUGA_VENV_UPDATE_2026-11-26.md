## Python installation and execution

`atlas.pythonPath` is a machine-scoped VS Code setting for the absolute Python
executable on the extension host. The trusted daemon equivalent is
`DAFTAR_PYTHON_PATH`. It reaches both portable workbench environment creation and
managed Linux Python jobs. Invalid explicit configuration fails without silently
choosing another interpreter.

The previous managed verifier accepted `pyvenv.cfg` after system site-packages
were enabled. Python's isolated flag alone does not undo that setting. Verification
now rejects this configuration, checks actual interpreter isolation and records
the configuration hash. Legacy environment receipts are rechecked for isolation;
new receipts also require the pinned configuration bytes.

The portable acceptance creates a real venv, installs a generated local wheel,
runs it with that venv's exact interpreter, proves the package is unavailable to
base Python, and uninstalls it. No package index or provider call is needed. The
managed integration exercises the real environment service and host-job controller
with a direct-process test launcher; the separate installed-editor CI test exercises
real Linux tmux.

VS Code supplies an Electron executable as its Node runtime. The trusted managed
Python and design-installer wrappers now explicitly select Node mode when launched
through the scrubbed host shell. Python, ordinary shell commands, APT and extraction
keep their scrubbed child environments. The managed suite and the design wrapper's
invalid-manifest rejection were executed using the actual downloaded editor binary
in Node mode; this is separate from graphical editor acceptance.

See [the Python workflow](PYTHON_VENV_WORKFLOW.md) and
[the source-bound venv receipt](PYTHON_VENV_VALIDATION_2026-11-26.json).
VS Code, Node, Rust, Blender, Unreal and GPU drivers retain their own runtimes;
Python venv isolation applies to Python packages.
