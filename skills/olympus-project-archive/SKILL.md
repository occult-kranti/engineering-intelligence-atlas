# Olympus archive — company adapter

Use the published archive contract pinned in [source-pins.json](references/source-pins.json). Its branch publication is distinct from default-branch integration or deployment. This runtime adapter does not copy private project conversations or install the source package's validator.

## Recover within the case scope

1. Read the actual Olympus index, latest dated research/release checkpoint and operating protocol. Keep `occult-kranti/india-corporate-intelligence` as the canonical application unless the owner selects another destination.
2. Inspect default and relevant feature branches at exact commits before calling work unpushed. A published unmerged branch already contains pushed work. Preserve newer and concurrent changes.
3. Inventory only accessible case artifacts and prior context. Classify exact bytes, redacted exports, partial exports, checkpoint summaries, memory leads, unavailable items and held metadata. State the known denominator and missing transcript coverage.
4. Record original and retained hashes, filename, size, source/version and dates. Deduplicate identical bytes while preserving origins. Keep original and redacted exports distinguishable.
5. Keep privacy-held material, private chat locators, credentials and rights-uncleared sources out of public derivatives. Preserve qanon-dossier and occult-corpus-research holds and the DIALOG/Frankism distinction. Prior public presence does not grant permission to re-export held material.

## Create a reviewable release

Use `project-research-consolidation` for the company index and source-linked summary. Link already-published originals instead of duplicating them. Keep rejected joins, uncertainty and source-reading depth near conclusions. An archive receipt does not validate an investigative claim or admit it into the public factual graph.

Prepare an explicit changeset with expected base commit, paths, source/artifact hashes and verification commands. If using the source archive validator, obtain its pinned package and read its contract first; it is not supplied by this adapter. Byte/schema validation cannot establish source truth, rights, independence or deployment.

Route the release to `github-release` under existing authorization. Verify the resulting remote ref/content. Keep `drafted`, `tested`, `reviewed`, `pushed` and `deployed` separate. Preserve the last verified deployment and report a failed deployment independently of archive success.

Return exact repository links, coverage counts, missing/held items, owners and concrete next records needed. Do not say all chats were archived unless the accessible universe and every export were actually verified. Route procedural lessons through `round-based-skill-evolution` and scoped accepted knowledge to Donna's native brain.

Use `node scripts/resource-router.mjs --skill olympus-project-archive --limit 6` only when available. The task contract and collaboration protocol retain company scope, capability and budget boundaries.
