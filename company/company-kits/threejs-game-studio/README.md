# Daftar 3D Game Studio

This reusable kit installs the company, five departments, named specialist assignments, shared-service contracts, a six-step roadmap and a linked whiteboard through the existing native command boundary.

The canonical definition is [`index.json`](../index.json). Run the company-kit installer first, then the company skill refresh described in [`COMPANY_SETUP_REFRESH.md`](../../../project/COMPANY_SETUP_REFRESH.md). Reapplying adds missing skills while preserving saved employee priority, paused states, completed roadmap evidence and owner board edits.

## Ownership

- **Company director**: Scoped studio director.
- **Knowledge curator**: Studio source and evidence curator.
- **Quality reviewer**: Independent studio acceptance reviewer.
- **Office steward**: Studio blueprint and ownership steward.
- **World designer and technical artist**: Procedural scene, game art and heritage geometry specialist.
- **Local model tools engineer**: Bounded local inference and engine integration engineer.
- **Scene acceptance reviewer**: Independent interaction, geometry and performance reviewer.

## Delivery sequence

1. **Pin the studio resources and engine sources**. Record the Three.js studio, reviewed model metadata, OpenCodeGameStudios module revision and engine/resource licenses. Acceptance: exact source refs and availability states.
2. **Define one playable scene and acceptance target**. Specify first-person/player controls, geometry scale, source fidelity and observable interactions. Use measured or sourced heritage geometry only where the evidence supports the precision claimed.
3. **Build the original playable scene**. Use the current scene workbench and relevant game/art modules. Acceptance: an executable artifact and controls demonstrated with real input. Keep source/model outputs distinguishable.
4. **Evaluate optional local model assistance**. Run bounded unseen prompts only when the actual model and device are available. Acceptance: model revision, measured latency, original outputs and failure cases; mock adapter tests do not count as inference.
5. **Verify geometry, input and performance**. Independently test keyboard/pointer input, reset behavior, frame timings and geometry provenance. Acceptance: raw observations and failed cases tied to the exact artifact.
6. **Archive the accepted scene and next improvement**. Link source refs, original assets, build and review receipts in Donna Brain; select one evidence-backed next round. Acceptance: retrievable artifacts and explicit unresolved limits.

## Operating boundary

Creation is configuration. It makes no provider requests, starts no workers and changes no existing budget or permissions. Source presence, installation, mock tests, actual execution and deployment have separate evidence states. Reuse the current native company if an earlier queued request has already created it; resolve its actual ID before applying this kit rather than creating a same-name duplicate.
