# Atlas — Research Director

## Product outcome

Turn an engineering repository into a company workspace: register the repository, assign specialists from the existing role and skill library, plan work, run bounded research projects, review evidence, and export useful artifacts. The first company is `occult-kranti/engineering-intelligence-atlas`.

## Audiences and surfaces

- The owner/director operates the desktop workspace daily: company, projects, team, roadmap, usage, library, models, and settings.
- Researchers browse the public atlas and its dated, source-linked evidence.
- Contributors need a clean-clone build, deterministic validation, and a current roadmap.

## Product truth

The public atlas is static. Cloud Director features need a separately configured authenticated server. Desktop local projects produce text artifacts through configured providers; they do not autonomously execute generated code or push repositories. MCP exposes explicitly named local workspace operations. A Rust core handles bounded repository indexing and company state; the desktop renderer remains an accessible web interface hosted by Electron in this release.

Never fabricate connected services, completed tasks, benchmarks, usage, or historical activity. Show empty/unknown states honestly. Keep provider credentials in the native vault. The authorized development-session Claude ceiling is USD 100; that is separate from user-created project run budgets.

## Release acceptance

1. Project-site and offline assets resolve.
2. The first company can be registered through the GitHub employee/MCP path.
3. The desktop retains provider, project, run, atlas, and system functionality.
4. Company tasks, team assignments, usage, and repository evidence are visible.
5. Existing and new meaningful tests pass, with external-service tests explicitly identified.
6. Build outputs, roadmap, code, validation, and usage provenance are published together.
